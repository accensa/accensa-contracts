Accensa relies on two purpose-built Soroban contracts deployed on the Stellar Testnet.

These contracts never touch the x402 payment path and are strictly non-custodial. They do not escrow funds between payers and merchants.

## ReceiptAnchor

The `ReceiptAnchor` contract stores batch commitments of settled payments. It serves as an immutable, on-chain truth ledger for agent operators.

### `initialize`
One-time setup binding the contract to the merchant address. Callable once; every later call fails with `AlreadyInitialized`.

```rust
fn initialize(env: Env, merchant: Address) -> Result<(), Error>
```
- **Authentication:** None (first caller sets the merchant; deploy and initialize in the same transaction).

### `anchor_batch`
Writes a Merkle root representing a batch of payments to persistent storage and returns the assigned batch id (sequential, starting at 1).

```rust
fn anchor_batch(env: Env, root: BytesN<32>, count: u32, period_start: u64, period_end: u64) -> Result<u64, Error>
```
- **Authentication:** Requires the merchant's signature (`require_auth`).
- **Emits:** `anchored` event carrying the batch id and the stored `BatchRecord`.
- **Returns:** The assigned `batch_id`.
- **Errors:** `BatchTooLarge` if `count` exceeds `MAX_BATCH_SIZE`. `AnchorRateLimited` if the caller's token bucket is empty (only enforced when a rate limit is configured).

### `set_anchor_rate_limit`
Configures a token-bucket rate limit on `anchor_batch`. The bucket holds up to `burst_capacity` tokens; each anchor spends one, and the bucket refills one token every `refill_interval_secs` seconds (capped at the burst). A fresh bucket — first anchor, or first after a config change — starts full, so the first `burst_capacity` anchors pass back-to-back. Setting both parameters to `0` disables rate-limiting entirely (the default).

```rust
fn set_anchor_rate_limit(env: Env, burst_capacity: u32, refill_interval_secs: u32) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Caps:** `burst_capacity ≤ 1000`, `refill_interval_secs ≤ 86,400` (24 h).
- **Errors:** `InvalidRateLimitConfig` if one parameter is zero while the other is set, or either exceeds its cap.
- **Tracking overhead:** one 12-byte persistent entry per identity, written only while a limit is enabled; when disabled, `anchor_batch` costs a single instance read.

### `get_anchor_rate_limit`
Returns the current rate-limit configuration (read-only). Returns `{0, 0}` (disabled) if unset.

```rust
fn get_anchor_rate_limit(env: Env) -> RateLimitConfig
```

### `get_batch`
Reads a stored batch commitment.

```rust
fn get_batch(env: Env, batch_id: u64) -> Result<BatchRecord, Error>
```
- **Errors:** `BatchNotFound` if the id was never anchored.

### `verify_receipt`
A read-only convenience function for on-chain receipt verification. Proof siblings are combined with sorted-pair SHA-256 hashing (the lexicographically smaller hash goes first), so proofs carry no left/right position flags. Note that the Accensa SDK performs the exact same verification locally off-chain to avoid RPC overhead.

```rust
fn verify_receipt(env: Env, batch_id: u64, leaf: BytesN<32>, proof: Vec<BytesN<32>>) -> Result<bool, Error>
```
- **Errors:** `BatchNotFound` if the batch id does not exist. `ProofTooLong` if the proof exceeds the maximum valid length (derived from `MAX_BATCH_SIZE`; call `get_max_proof_len` to discover the limit at runtime).

### `verify_receipt_by_root`
Verify a receipt against any root in the historical ring buffer. Returns `true` if the root is in the buffer AND the Merkle proof is valid. Useful for delayed off-chain processes that may not know the exact `batch_id`.

```rust
fn verify_receipt_by_root(env: Env, root: BytesN<32>, leaf: BytesN<32>, proof: Vec<BytesN<32>>) -> Result<bool, Error>
```
- **Errors:** `NotInitialized` if the contract has not been initialized. `RootNotFound` if the root is not in the ring buffer. `ProofTooLong` if the proof exceeds the maximum valid length.

### `get_root_buffer`
Returns the current ring buffer of historical Merkle roots (read-only). The buffer is bounded to `ROOT_BUFFER_SIZE` entries; oldest roots are evicted when full.

```rust
fn get_root_buffer(env: Env) -> Vec<BytesN<32>>
```

### `get_root_buffer_size`
Returns the maximum number of historical roots retained in the ring buffer (read-only).

```rust
fn get_root_buffer_size(env: Env) -> u32
```

### `get_max_proof_len`
Returns the maximum valid Merkle proof length, derived from `MAX_BATCH_SIZE`. Clients should call this rather than hard-coding the limit so they stay in sync if the constant is ever tuned.

```rust
fn get_max_proof_len(env: Env) -> u32
```

## RefundVault

The `RefundVault` contract holds merchant float and executes refunds according to self-declared policy bounds.

### `initialize`
One-time setup binding the vault to the merchant, the refund token (any SEP-41 token contract address — the USDC SAC by default), and the refund window in ledgers. A window of `0` disables expiry entirely.

```rust
fn initialize(env: Env, merchant: Address, token: Address, refund_window_ledgers: u32) -> Result<(), Error>
```

### `deposit`
Transfers refund float from the merchant's wallet to the contract. `from` must equal the merchant address; anything else fails with `Unauthorized`.

```rust
fn deposit(env: Env, from: Address, amount: i128) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.

### `refund`
Executes a refund to a specified address, provided it occurs within the merchant's declared refund window.

```rust
fn refund(env: Env, payment_ref: BytesN<32>, recipient: Address, amount: i128, paid_at_ledger: u32) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Constraints:** Fails with `AlreadyRefunded` if the `payment_ref` was refunded before, with `WindowExpired` if the current ledger exceeds `paid_at_ledger + window` (boundary ledger still refundable; skipped when the window is `0`), and with `InsufficientFloat` if the vault balance cannot cover `amount`.
- **Emits:** `refunded` event carrying the payment reference and the stored `RefundRecord`.

### `withdraw`
Returns float from the vault to an address of the merchant's choosing.

```rust
fn withdraw(env: Env, amount: i128, to: Address) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `InsufficientFloat` if the vault balance is below `amount`.

### `propose_policy`
Proposes a new refund window. The change is not applied immediately; the admin must call `execute_policy` after the timelock (17,280 ledgers, ~24 hours) has elapsed. Proposing a new policy overwrites any existing pending proposal.

```rust
fn propose_policy(env: Env, ledgers: u32) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.

### `execute_policy`
Executes a pending policy change. Fails if no policy is pending (`NoPendingPolicy`) or if the timelock has not yet expired (`TimelockNotExpired`).

```rust
fn execute_policy(env: Env) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `NoPendingPolicy` if no proposal exists, `TimelockNotExpired` if the timelock delay has not passed.

### `get_pending_policy`
Returns the current pending policy proposal, if any.

```rust
fn get_pending_policy(env: Env) -> Option<PolicyProposal>
```

### `get_policy_timelock`
Returns the policy timelock delay in ledgers (read-only).

```rust
fn get_policy_timelock(env: Env) -> u32
```

### `get_refund`
Looks up the refund record for a payment reference, if one exists.

```rust
fn get_refund(env: Env, payment_ref: BytesN<32>) -> Option<RefundRecord>
```
