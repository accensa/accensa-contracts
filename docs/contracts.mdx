The Accensa protocol workspace implements a suite of purpose-built Soroban smart contracts. Eleven contracts are compiled to standalone deployable WASM bytecode and tracked with size budgets in `.wasm-budget.json`:

- **`receipt_anchor`**: Stores batch commitments of settled payments, providing an immutable on-chain truth ledger for receipt verification.
- **`refund_vault`**: Holds merchant refund float and executes policy-bounded, fee-adjusted refunds.
- **`refund_policy_time`**: Evaluates ledger-window and time-based refund policy constraints.
- **`refund_policy_vdf`**: Evaluates Verifiable Delay Function (VDF) delay proofs for time-locked refunds.
- **`refund_vault_factory`**: Factory contract deploying standardized, parameterized `RefundVault` instances.
- **`governance`**: DAO governance contract managing optimistic execution proposals, vetoes, and voting rights.
- **`multisig_account`**: Multi-signature smart contract account with `m`-of-`n` threshold authorization and signer recovery.
- **`receipt_shard`**: Sharded storage partition for receipt commitments to ensure high-throughput scaling without state contention.
- **`state_channel`**: State channel contract supporting HTLCs, disputes, and cooperative off-chain payment settlement.
- **`stream_vault`**: Streaming payment vault supporting continuous per-second and linear token disbursements.
- **`upto_authorization`**: Pre-authorization scheme allowing buyers to sign an "up-to" cap with slippage protection for meter-based payments without locking full escrow.

For the broader system architecture and auxiliary contract crates, see [docs/ARCHITECTURE.md](ARCHITECTURE.md). For deployed addresses across networks, refer to [DEPLOYMENTS.md](../DEPLOYMENTS.md).

### Custody and Funds Safety

Accensa contracts never touch the core off-chain x402 payment path. Custody models vary by contract role:
- **`ReceiptAnchor`** (and `receipt_shard`) is strictly non-custodial: it stores cryptographic commitments (Merkle roots, ZK proofs) and never holds tokens or escrows funds between payers and merchants.
- **`RefundVault`** is custodial by design: it holds merchant-deposited token float to guarantee automated refund fulfillment within merchant-defined policy bounds and optional yield deployments.
- Other value-bearing contracts (`state_channel`, `stream_vault`) hold funds under their own explicit escrow and settlement rules; see [ARCHITECTURE.md](ARCHITECTURE.md).


## ReceiptAnchor

The `ReceiptAnchor` contract stores batch commitments of settled payments. It serves as an immutable, on-chain truth ledger for agent operators.

### `initialize`
One-time setup binding the contract to the merchant address and registering the receipt shard WASM hash. Callable once; every later call fails with `AlreadyInitialized`.

```rust
fn initialize(env: Env, merchant: Address, shard_wasm_hash: BytesN<32>) -> Result<(), Error>
```
- **Authentication:** None (first caller sets the merchant; deploy and initialize in the same transaction).

### `anchor_batch`
Writes a Merkle root representing a batch of payments to persistent storage for a specific shard partition and returns the assigned batch id (sequential, starting at 1).

```rust
fn anchor_batch(env: Env, shard_id: u64, root: BytesN<32>, count: u32, period_start: u64, period_end: u64) -> Result<u64, Error>
```
- **Authentication:** Requires the merchant's signature (`require_auth`).
- **Emits:** `anchored` event carrying the batch id and the stored `BatchRecord`.
- **Returns:** The assigned `batch_id`.
- **Errors:** `BatchTooLarge` if `count` exceeds `MAX_BATCH_SIZE`. `AnchorRateLimited` if the caller's token bucket is empty (only enforced when a rate limit is configured).

### `set_anchor_rate_limit`
Configures a token-bucket rate limit on `anchor_batch`. The bucket holds up to `burst_capacity` tokens; each anchor spends one, and the bucket refills one token every `refill_interval_secs` seconds (capped at the burst). A fresh bucket — first anchor, or first after a config change — starts full, so the first `burst_capacity` anchors pass back-to-back. Setting both parameters to `0` disables rate-limiting entirely (the default).

```rust
fn set_anchor_rate_limit(env: Env, burst_capacity: u32, refill_interval_secs: u32) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Caps:** `burst_capacity ≤ 1000`, `refill_interval_secs ≤ 86,400` (24 h).
- **Errors:** `InvalidRateLimitConfig` if one parameter is zero while the other is set, or either exceeds its cap.
- **Tracking overhead:** one 12-byte persistent entry per identity, written only while a limit is enabled; when disabled, `anchor_batch` costs a single instance read.

### `get_anchor_rate_limit`
Returns the current rate-limit configuration (read-only). Returns `{0, 0}` (disabled) if unset.

```rust
fn get_anchor_rate_limit(env: Env) -> RateLimitConfig
```

### `get_batch`
Reads a stored batch commitment for a given shard.

```rust
fn get_batch(env: Env, shard_id: u64, batch_id: u64) -> Result<BatchRecord, Error>
```
- **Errors:** `BatchNotFound` if the id was never anchored.

### `verify_receipt`
A read-only convenience function for on-chain receipt verification within a shard. Proof siblings are combined with sorted-pair SHA-256 hashing (the lexicographically smaller hash goes first), so proofs carry no left/right position flags. Note that the Accensa SDK performs the exact same verification locally off-chain to avoid RPC overhead.

```rust
fn verify_receipt(env: Env, shard_id: u64, batch_id: u64, leaf: BytesN<32>, proof: Vec<BytesN<32>>) -> Result<bool, Error>
```
- **Errors:** `BatchNotFound` if the batch id does not exist. `ProofTooLong` if the proof exceeds the maximum valid length (derived from `MAX_BATCH_SIZE`; call `get_max_proof_len` to discover the limit at runtime).

### `verify_receipt_by_root`
Verify a receipt against any root in the historical ring buffer for a shard. Returns `true` if the root is in the buffer AND the Merkle proof is valid. Useful for delayed off-chain processes that may not know the exact `batch_id`.

```rust
fn verify_receipt_by_root(env: Env, shard_id: u64, root: BytesN<32>, leaf: BytesN<32>, proof: Vec<BytesN<32>>) -> Result<bool, Error>
```
- **Errors:** `NotInitialized` if the contract has not been initialized. `RootNotFound` if the root is not in the ring buffer. `ProofTooLong` if the proof exceeds the maximum valid length.

### `get_root_buffer`
Returns the current ring buffer of historical Merkle roots for a shard (read-only). The buffer is bounded to `ROOT_BUFFER_SIZE` entries; oldest roots are evicted when full.

```rust
fn get_root_buffer(env: Env, shard_id: u64) -> Vec<BytesN<32>>
```

### `get_root_buffer_size`
Returns the maximum number of historical roots retained in the ring buffer (read-only).

```rust
fn get_root_buffer_size(env: Env) -> u32
```

### `get_max_proof_len`
Returns the maximum valid Merkle proof length, derived from `MAX_BATCH_SIZE`. Clients should call this rather than hard-coding the limit so they stay in sync if the constant is ever tuned.

```rust
fn get_max_proof_len(env: Env) -> u32
```

## RefundVault

The `RefundVault` contract holds merchant float and executes refunds according to self-declared policy bounds.

### `initialize`
One-time setup binding the vault according to `VaultInit` parameters (merchant, token, refund window, etc.). Callable once; every later call fails with `AlreadyInitialized`.

```rust
fn initialize(env: Env, init: VaultInit) -> Result<(), Error>
```

### `deposit`
Transfers refund float from the merchant's wallet to the contract, with optional coupon support. `from` must equal the merchant address; anything else fails with `Unauthorized`.

```rust
fn deposit(env: Env, from: Address, amount: i128, coupon_id: Option<u64>) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.

### `refund`
Executes a refund to a specified address, provided it occurs within the merchant's declared refund window, wall-clock deadline, and VDF delay proof (if enabled).

```rust
fn refund(env: Env, payment_ref: BytesN<32>, recipient: Address, amount: i128, paid_at_ledger: u32, payment_amount: i128, vdf_proof: Option<BytesN<256>>, nonce: u64) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Constraints:** Fails with `ExceedsPayment` if cumulative refunds would exceed `payment_amount`, with `WindowExpired` if the current ledger exceeds `paid_at_ledger + window` (boundary ledger still refundable; skipped when the window is `0`), with `RefundExpired` if the policy deadline has strictly passed, and with `InsufficientFloat` if the vault balance cannot cover `amount`.
- **Fees:** When a fee is configured (`set_fee_bps`), the claim is split into the recipient's `payout` and a `fee` that rounds up to the fee recipient (`payout + fee == amount`). An unset fee recipient defaults to the merchant; configuring the vault's own address is rejected.
- **Emits:** `RefundEvent` carrying the payment reference and the stored `RefundRecord` (including the per-call `fee`).

### `claim_batch`
Refunds multiple claims in one transaction. Each claim is processed with exactly the same logic, checks and fees as a single `refund`, so the batch needs only one merchant signature and one reentrancy-lock acquisition. The batch is **atomic**: if any claim fails, the error is returned and the whole invocation — its transfers, storage writes and events — is reverted, so either every claim persists or none do.

```rust
fn claim_batch(env: Env, claims: Vec<RefundClaim>, nonce: u64) -> Result<(), Error>
```

- **Authentication:** Requires the merchant's signature (checked once for the whole batch).
- **Constraints:** Each element is validated independently, exactly as for `refund`: `InvalidAmount` for a non-positive amount, `SelfTransfer` for the vault's own address, `ExceedsPayment` for a legacy record or a cumulative over-ceiling, `WindowExpired` / `RefundExpired` when outside the policy, and `InsufficientFloat` if the vault cannot cover the element at the point it is processed. The float is read afresh before **every** element, so a batch cannot overdraw the float any more than the equivalent sequence of single refunds; repeated `payment_ref`s accumulate against the same ceiling across elements.
- **`RefundClaim` fields:** `payment_ref: BytesN<32>`, `recipient: Address`, `amount: i128`, `paid_at_ledger: u32`, `payment_amount: i128` — the same arguments a `refund` call takes, as a single struct.
- **Emits:** one `RefundEvent` per claim, in claim order.
- **Empty batch:** an empty `claims` vector succeeds as a no-op.

### `process_batch`
Processes up to `MAX_BATCH_SIZE` (100) refund requests in a single
transaction. Authentication is checked **once** for the whole batch, and the
refund window, current ledger, token address and vault balance are loaded once
into a shared context rather than once per item — the vault makes a single
`balance` cross-contract call for the entire batch. The cap is set at the
largest batch that fits mainnet's 16 KiB contract-event budget; a single
compact `BatchRefundEvent` is emitted for the whole batch instead of one
`RefundEvent` per item.

```rust
fn process_batch(env: Env, refunds: Vec<RefundParam>, nonce: u64) -> Result<Vec<bool>, Error>
```
- **Authentication:** Requires the merchant's signature (the merchant may be a
  relayer contract account).
- **Errors:** `BatchTooLarge` if more than 100 items, `Paused` if the vault is
  paused.
- **Returns:** one `bool` per refund in submission order — `true` = executed,
  `false` = that item failed validation (e.g. insufficient float, window
  expired) and was skipped; the rest of the batch still processes.
- **Emits:** `batch_refund_event` with parallel `payment_refs` / `results`
  vectors aligned 1:1 with the input.

### `withdraw`
Returns float from the vault to an address of the merchant's choosing.

```rust
fn withdraw(env: Env, amount: i128, to: Address) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `InsufficientFloat` if the vault balance is below `amount`.

### `propose_policy`
Proposes a new refund policy: a window (in ledgers), a wall-clock deadline (Unix timestamp, `0` = no deadline), and a VDF delay (in ledgers, `0` = disabled). The change is not applied immediately; the admin must call `execute_policy` after the timelock (17,280 ledgers, ~24 hours) has elapsed. Proposing a new policy overwrites any existing pending proposal.

```rust
fn propose_policy(env: Env, ledgers: u32, deadline: u64, vdf_delay: u32) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.

### `execute_policy`
Executes a pending policy change. Fails if no policy is pending (`NoPendingPolicy`) or if the timelock has not yet expired (`TimelockNotExpired`). Applies both the new window and the new deadline.

```rust
fn execute_policy(env: Env) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `NoPendingPolicy` if no proposal exists, `TimelockNotExpired` if the timelock delay has not passed.

### `get_pending_policy`
Returns the current pending policy proposal, if any.

```rust
fn get_pending_policy(env: Env) -> Option<PolicyProposal>
```

### `get_policy_timelock`
Returns the policy timelock delay in ledgers (read-only).

```rust
fn get_policy_timelock() -> u32
```

### `get_refund_deadline`
Returns the configured policy deadline as a Unix timestamp (read-only). `0` means no deadline is configured.

```rust
fn get_refund_deadline(env: Env) -> u64
```

### `set_fee_bps`
Sets the refund fee rate in basis points (`0` = no fee, up to `10_000` = 100%). Admin auth required. Values above `10_000` return `InvalidRatio`. Emits `FeeConfigUpdatedEvent`. Extends the instance TTL.

```rust
fn set_fee_bps(env: Env, bps: u32) -> Result<(), Error>
```

### `set_fee_recipient`
Sets the address that collects the fee deducted from each refund. Setting the vault's own address returns `SelfTransfer`. Admin auth required. Emits `FeeConfigUpdatedEvent`. Extends the instance TTL.

```rust
fn set_fee_recipient(env: Env, recipient: Address) -> Result<(), Error>
```

### `get_fee_bps`
Returns the configured fee rate in basis points (read-only).

```rust
fn get_fee_bps(env: Env) -> u32
```

### `get_fee_recipient`
Returns the configured fee recipient, if any (read-only). At claim time an unset recipient falls back to the merchant (admin).

```rust
fn get_fee_recipient(env: Env) -> Option<Address>
```

### `get_refund`
Looks up the refund record for a payment reference, if one exists.

```rust
fn get_refund(env: Env, payment_ref: BytesN<32>) -> Option<RefundRecord>
```

### `add_oracle`
Whitelists an oracle contract implementing the standard `Oracle` interface (`get_price(feed_id)` and `get_last_update_ledger(feed_id)`). Merchant auth required. The aggregator queries every whitelisted oracle and takes the median of the fresh values, so a single provider cannot unilaterally move the aggregated price.

```rust
fn add_oracle(env: Env, oracle: Address) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `OracleAlreadyAdded` if the oracle is already whitelisted.

### `remove_oracle`
Removes an oracle from the whitelist. Merchant auth required.

```rust
fn remove_oracle(env: Env, oracle: Address) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `OracleNotFound` if the oracle is not whitelisted, `NoOraclesConfigured` if the whitelist is empty.

### `get_oracles`
Returns the current oracle whitelist, in insertion order (read-only).

```rust
fn get_oracles(env: Env) -> Vec<Address>
```

### `get_median_price`
Queries every whitelisted oracle for `feed_id` and returns the median of the values fresher than `max_staleness_ledgers` (`0` = never stale). Read-only.

```rust
fn get_median_price(env: Env, feed_id: BytesN<32>, max_staleness_ledgers: u32) -> Result<i128, Error>
```
- **Errors:** `NoOraclesConfigured` if the whitelist is empty, `StaleOracleData` if every whitelisted oracle is stale.

### `set_oracle_policy`
Installs (or replaces) the dynamic oracle policy gating refunds: while a policy is set, `refund` and `process_batch` only pay out when the aggregated median satisfies the condition (e.g. the asset price is below the SLA floor). Merchant auth required.

```rust
fn set_oracle_policy(env: Env, policy: OraclePolicy) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Emits:** `oracle_policy_set_event` carrying the feed and the full condition.

### `clear_oracle_policy`
Removes the dynamic oracle policy, restoring purely time-window-based refunds. Merchant auth required.

```rust
fn clear_oracle_policy(env: Env) -> Result<(), Error>
```
- **Authentication:** Requires the merchant's signature.
- **Errors:** `NoOraclePolicy` if no policy is installed.
- **Emits:** `oracle_policy_cleared_event` carrying the feed that was cleared.

### `get_oracle_policy`
Returns the currently installed oracle policy, if any (read-only).

```rust
fn get_oracle_policy(env: Env) -> Option<OraclePolicy>
```
